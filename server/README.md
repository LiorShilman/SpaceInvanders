# server (Phase 1)

שרת Colyseus — **פרוסת בדיקה (proof-of-concept) קיימת ועובדת**, לא עדיין השרת הסמכותי (authoritative) המלא שהיה מתואר כאן קודם.

## מה יש היום

חדר אחד (`src/rooms/co-op-survival.ts`, `co_op_survival`) שמחבר עד 4 שחקנים ומשדר לכולם את המיקום/סיבוב של כל ספינה מחוברת. כל לקוח עדיין מדמה את כל המשחק שלו בעצמו בצד הלקוח — בדיוק כמו סינגלפלייר — והשרת רק **משדר מיקומים בין לקוחות**, בלי מצב משותף של אויבים/גלים/בוסים, בלי בדיקת פגיעות בצד שרת, ובלי שום אימות (לקוח יכול לדווח כל מיקום). המטרה של הפרוסה הזו הייתה לוודא שכל שרשרת התקשורת בפועל עובדת מקצה לקצה (Colyseus room lifecycle, סינכרון schema, הרשמה לעדכונים בצד לקוח) לפני שמשקיעים בהעברת כל הסימולציה מ-`Scene.tsx` לרוץ בצד שרת.

**אומת** ב-Playwright עם שני דפדפנים נפרדים: שני לקוחות מתחברים עם session id שונה, לקוח A מזיז את הספינה שלו ולקוח B רואה בפועל ספינה מרוחקת (בצבע זהב, ראו `RemoteShip.tsx`) מופיעה ונעה במיקום הנכון בזמן אמת; ניתוק לקוח מנקה את הספינה המרוחקת אצל הצד השני.

## איך מפעילים מקומית

```bash
npm install -w server      # פעם אחת
npm run dev -w server      # מאזין על :2567
```

בצד הלקוח, גישה למשחק עם `?coop=1` בכתובת (למשל `http://localhost:5173/?coop=1`) מפעילה את שכבת הרשת — בלי הדגל, שום קוד רשת לא רץ בכלל, וחוויית הסינגלפלייר הרגילה נשארת בדיוק כפי שהייתה.

## מה עדיין חסר לפני שזה "השרת הסמכותי" האמיתי

- `src/sim/` — סכימת מצב המשחק המשותפת: אויבים, פורמציה, גלים, בוסים — הכול עדיין קיים רק בצד לקוח, ולכל שחקן יש עותק נפרד לגמרי (אין באמת "אותם אויבים" בין שני שחקנים).
- בדיקת פגיעות/נזק בצד שרת (anti-cheat) — כרגע כל לקוח מדווח את המיקום שלו בלי שום אימות.
- `src/waves/` — מחולל הגלים הפרוצדורלי בצד שרת.
- `src/rooms/pvp-asymmetric.ts` — חדר ה-PvP (Phase 3), תלוי בכל הנ"ל.
- פריסה לשרת הבית (עדיין רץ רק מקומית — ראו `homelab-deploy` כשמגיע הזמן).
