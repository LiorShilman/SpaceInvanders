# server (Phase 1)

שרת Colyseus — **פרוסת בדיקה (proof-of-concept) קיימת ועובדת**, לא עדיין השרת הסמכותי (authoritative) המלא שהיה מתואר כאן קודם.

## מה יש היום

חדר אחד (`src/rooms/co-op-survival.ts`, `co_op_survival`) שמחבר עד 4 שחקנים:

- **מיקום ספינה**: כל לקוח מדווח את המיקום/סיבוב של הספינה שלו, והשרת משדר לכל השאר — כל ספינה עדיין מדומה לגמרי בצד הלקוח שלה.
- **פורמציה ואויבים משותפים**: השרת הוא זה שמחשב את מיקום הפורמציה (נדנוד + התקדמות) ומחזיק מערך 40 בוליאנים ("איזה משבצת עדיין חי") ומספר הגל — **כולם מסתכלים על אותה פורמציה, ואותם אויבים בדיוק**. כשלקוח מזהה פגיעה מקומית הוא לא הורג את האויב בעצמו — הוא רק **מדווח** לשרת; ברגע שהשרת מאשר (המערך המשותף משתנה), **כל לקוח** (כולל היורה) מיישם את ההריגה. כשכל 40 מתים, השרת מאפס לגל חדש ומקדם את המספר.
- **חילוץ (revive)**: פגיעה קטלנית עם שותף מחובר לא עולה חיים — הספינה "מושבתת" (`downed`, שדה משותף על הסכמה) ומחכה. שותף לא-מושבת שנשאר בטווח קרוב (`REVIVE.radius`) ברצף למשך `REVIVE.channelDuration` מחלץ — בריאות חלקית חוזרת, בלי לעלות חיים בכלל. אם אף אחד לא הגיע תוך `REVIVE.timeout`, נופל בדיוק לאותה תוצאה שפגיעה קטלנית רגילה הייתה נותנת (איבוד חיים/סוף משחק). סינגלפלייר (או קו-אופ בלי שותף מחובר) לא נכנס למצב הזה בכלל — מתנהג בדיוק כמו קודם.

**מה זה מדויק לא כולל עדיין** (ראו את התיעוד המלא בראש `co-op-survival.ts`): בריאות/מצב "כבד" לכל אויב (כל פגיעה משותפת היא קטלנית — אין 2 פגיעות לכבד בקו-אופ), בוסים (גל שהוא כפולה של 5 עדיין מייצר בוס מקומי בלבד, בלי סנכרון), שום אימות פגיעה בצד שרת (אנטי-צ'יט), צורת/פיזור הפורמציה (כל לקוח עדיין מגריל Heavy/צורה בעצמו), וחילוץ רק דרך פגיעה ישירה (`damageShip`) — פריצת פורמציה (`handleInvasion`) עדיין תמיד עולה חיים ישירות, גם בקו-אופ.

**אומת** ב-Playwright עם שני דפדפנים נפרדים: מיקום ספינה מסתנכרן בזמן אמת; שני הלקוחות רואים את אותה פורמציה בדיוק; פגיעה אמיתית של בולט אצל שחקן A (לא רק דרך hook דיבאג) גורמת להריגה גם אצל B; פגיעה קטלנית עם שותף מחובר מכניסה למצב מושבת (לא איבוד חיים), השותף רואה זאת דרך הסכמה המשותפת, ירי מנוטרל בזמן ההשבתה, חילוץ אמיתי (לא רק קריאת debug hook) משחזר בריאות חלקית בלי לעלות חיים, ופקיעת זמן ללא חילוץ נופלת בדיוק לתוצאת איבוד-חיים הרגילה; ניתוק מנקה נכון את שני הצדדים. כמה באגים אמיתיים נמצאו ותוקנו בדרך — ראו קומיטים (כולל אבחון סביבת בדיקה: שני משחקים תלת-ממדיים בו-זמנית בדפדפן headless אחד מאטים את קצב הפריימים של כל צד באופן ניכר — לא קיים בפועל כששני שחקנים אמיתיים משחקים כל אחד על המסך שלו).

## איך מפעילים מקומית

```bash
npm install -w server      # פעם אחת
npm run dev -w server      # מאזין על :2567
```

בצד הלקוח, גישה למשחק עם `?coop=1` בכתובת (למשל `http://localhost:5173/?coop=1`) מפעילה את שכבת הרשת — בלי הדגל, שום קוד רשת לא רץ בכלל, וחוויית הסינגלפלייר הרגילה נשארת בדיוק כפי שהייתה.

## מה עדיין חסר לפני שזה "השרת הסמכותי" האמיתי

- בריאות/Heavy/דייב/פלנקר/רימון/נובה/פיקאפים/הישגים/ניקוד — כולם עדיין מקומיים לגמרי ולא חלק מהמצב המשותף.
- בדיקת פגיעות/נזק אמיתית בצד שרת (anti-cheat) — כרגע לקוח יכול לדווח פגיעה על כל אינדקס, בלי שום בדיקת מרחק/זמן. חילוץ סובל מאותה בעיה: לקוח יכול לדווח `downed`/מיקום כרצונו.
- בוסים משותפים — כרגע רצים מקומית בלבד גם בגל שהוא כפולה של 5.
- חילוץ בפריצת פורמציה (`handleInvasion`) — כרגע רק פגיעה ישירה (`damageShip`) עוברת דרך מצב מושבת; פריצה תמיד עולה חיים.
- `src/waves/` — מחולל הגלים הפרוצדורלי + סנכרון צורת/פיזור הפורמציה (Heavy, shape) בצד שרת, כדי ששני שחקנים יראו בדיוק אותו מסך.
- `src/rooms/pvp-asymmetric.ts` — חדר ה-PvP (Phase 3), תלוי בכל הנ"ל.
- פריסה לשרת הבית (עדיין רץ רק מקומית — ראו `homelab-deploy` כשמגיע הזמן).

## תיעוד קוד

`server/src/rooms/co-op-survival.ts` עצמו הוא המקור הכי מעודכן לסקופ המדויק — התיעוד שם (הערת המחלקה + כל handler) מפרט בדיוק מה קיים ומה לא, ומתעדכן בכל שינוי.
